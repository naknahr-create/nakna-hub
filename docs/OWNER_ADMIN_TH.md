# หลังบ้านเจ้าของระบบ — นากนะ HUB

## เข้าใช้งาน

เปิด `/admin` ด้วยบัญชีที่ผูกเป็นเจ้าของระบบไว้ใน `hub_operators` เมนู “หลังบ้านเจ้าของ” ในสตูดิโอแสดงเฉพาะบัญชีที่มีสิทธิ์นี้ ลูกค้าทั่วไปเข้าถึงข้อมูลหลังบ้านไม่ได้ แม้เปิด URL หรือเรียก API โดยตรง

สิทธิ์เจ้าของระบบแยกจากสมาชิก Pro เจ้าของดูภาพรวมทั้งแพลตฟอร์มในหลังบ้านได้ ส่วนหน้าสถิติในสตูดิโอใช้กติกาสมาชิกเดียวกับลูกค้า การเป็นเจ้าของไม่ทำให้เกิดการสมัครหรือเรียกเก็บเงิน

### ผูกเจ้าของครั้งแรก

1. ให้เจ้าของเข้าสู่ระบบด้วย LINE และยืนยันว่าบัญชีนั้นเป็นบัญชีที่ต้องการจริง
2. ตรวจบัญชีและฮับที่เป็นเจ้าของใน D1 พร้อมตรวจว่ามีแถว `slot='operator'` ใน `hub_operators` แล้วหรือไม่ อย่าเลือกผู้สมัครคนแรกโดยอัตโนมัติ และอย่าใช้ชื่อแสดงผลเป็นหลักฐานยืนยันตัวตนเพียงอย่างเดียว
3. หลังอนุมัติการให้สิทธิ์ ตั้ง Worker runtime `ADMIN_LINE_USER_ID` เป็น LINE user ID ที่ยืนยันแล้วจาก provider เดียวกับ `LINE_LOGIN_CHANNEL_ID` ระบบจะผูก stable identity เมื่อบัญชีนั้นเรียกใช้ครั้งแรก หรือให้ผู้ดูแลฐานข้อมูลผูก identity ที่ตรวจแล้วโดยตรงตามกระบวนการควบคุมสิทธิ์ของตน
4. เปิดสตูดิโอใหม่แล้วเปิด `/admin` ตรวจว่าบัญชีลูกค้าปกติยังได้รับ HTTP 403 จาก `/api/operator`

โค้ดไม่สร้างเจ้าของจากผู้สมัครคนแรก ไม่ฝังชื่อ บัญชี หรือรหัส LINE ของเจ้าของไว้ใน Git และไม่เปลี่ยนผู้ถือสิทธิ์เดิมเมื่อแก้ environment variable การโอนเจ้าของต้องเป็นการดำเนินการที่ได้รับอนุมัติแยกต่างหาก

## หน้าที่มีให้ใช้งาน

| ส่วน | ใช้ทำอะไร |
| --- | --- |
| ภาพรวม | ดูบัญชีทั้งหมด บัญชีที่มีสิทธิ์ชำระแล้ว ฮับที่เผยแพร่ ยอดเข้าชม/คลิกตามช่วงเวลา แนวโน้มรายวัน และฮับยอดนิยม |
| ผู้ใช้ | ค้นหาชื่อ อีเมล หรือรหัสบัญชี กรอง Starter/Pro ดูสถานะสมาชิก รอบบิล สิ้นสุดสิทธิ์ และจำนวนฮับ |
| บันทึกผู้ใช้ | เก็บบันทึกสำหรับการดูแลลูกค้า และปิดคำขอติดต่อเรื่องอัปเกรด โดยไม่เปลี่ยนแพ็กเกจ |
| ฮับ | ค้นหาฮับ กรองสถานะ และพักหรือคืนการเผยแพร่พร้อมระบุเหตุผล |
| ประวัติ | ดูว่าใครทำอะไร กับรายการใด เมื่อไร และเหตุผลที่บันทึกไว้ |

ข้อมูลผู้ใช้และฮับแบ่งหน้า หน้าละ 25 รายการ บันทึกสำหรับทีมดูแลไม่รวมอยู่ใน API ของลูกค้าหรือหน้าสาธารณะ

## การอ่านตัวเลข

- ยอดเข้าชมและยอดคลิกนับเป็นครั้ง ไม่ใช่จำนวนคน ใช้หลักการเก็บยอดเดียวกับหน้าสถิติลูกค้า
- ช่วงเวลารายงานอิงเวลาไทย Asia/Bangkok ช่วง 7 และ 30 วันรวมวันนี้
- ตัวเลขสมัคร Pro อ้างอิง subscription โหมด live ที่มีสิทธิ์ชำระเงินยังไม่สิ้นสุด ไม่ใช่เพียงชื่อแพ็กเกจในบัญชี
- มูลค่าสมาชิกต่อเดือนเป็น **ค่าประมาณจากสมาชิกที่ยังมีสิทธิ์**: รายเดือน × 149 บาท บวก รายปี × 1,490 ÷ 12 บาท การยกเลิกต่ออายุยังนับถึงสิ้นสุดรอบที่ชำระไว้ ตัวเลขนี้ไม่ใช่ยอดเงินจริงที่รับในเดือนนั้น ไม่หักค่าธรรมเนียม การคืนเงิน หรือภาษี ใช้ Stripe ตรวจรายการเงินจริง
- บัญชีที่ไม่ให้ LINE ส่งอีเมลจะไม่มีอีเมลในรายการ ไม่สร้างอีเมลสมมติ

## การพักการเผยแพร่

การพักฮับสร้างข้อจำกัดแยกจากข้อมูลหน้าเดิม เจ้าของยังเก็บและแก้ไขฉบับร่างได้ แต่เผยแพร่ไม่ได้จนกว่าจะคืนสิทธิ์ หน้าสาธารณะ ลิงก์เปลี่ยนเส้นทาง และรูปที่เผยแพร่ผ่านฮับที่ถูกพักจะไม่เปิดให้ผู้ชมเข้าถึง รูปที่ถูกใช้ในฮับอื่นซึ่งยังเผยแพร่ตามปกติยังเข้าถึงได้

การคืนการเผยแพร่ยกเลิกข้อจำกัด โดยเคารพสถานะเผยแพร่/เก็บเข้าคลังล่าสุดของเจ้าของ ไม่สั่งเผยแพร่ฉบับร่างให้เอง ทุกการพัก/คืนต้องมีเหตุผล และบันทึกประวัติใน transaction เดียวกับการเปลี่ยนสถานะ หากบันทึกประวัติไม่สำเร็จ การเปลี่ยนสถานะต้องไม่สำเร็จด้วย

การพักฮับไม่ยกเลิกสมาชิกหรือคืนเงิน หากต้องจัดการรายการเงิน ให้ใช้กระบวนการของ Stripe แยกต่างหาก หลังบ้านนี้ไม่มีปุ่มแจก Pro เปลี่ยนแพ็กเกจ ยกเลิกสมาชิก หรือเรียกเก็บเงินแทนลูกค้า

## ปล่อยเวอร์ชันนี้

ใช้ migration `drizzle/0004_owner_admin.sql` ก่อน deploy โค้ด มีเพียง 3 ตารางใหม่และ 1 index:

```sh
npm run db:migrate:remote
npm run build
npm run deploy:cloudflare
```

หากรันผ่าน D1 Console ให้ใช้ SQL จากไฟล์เดียวกัน ตรวจว่าทั้ง 3 ตารางและ index ถูกสร้างครบ แล้วจึงบันทึกชื่อไฟล์ใน `d1_migrations` เพื่อให้ ledger ตรงกัน Migration นี้ไม่แก้บัญชี ไม่เปลี่ยนแพ็กเกจ ไม่ให้สิทธิ์เจ้าของ และไม่ลบข้อมูลเดิม

หากต้องย้อนเวอร์ชัน ให้คืน Worker build ก่อนหน้าโดยเก็บตารางและประวัติใหม่ไว้เพื่อการตรวจสอบ การย้อนโค้ดไปก่อนมีระบบพักฮับจะไม่บังคับข้อจำกัดการพักฮับ จึงต้องตรวจสถานะเหล่านั้นก่อนย้อน ห้ามล้างข้อมูลหรือประวัติเพียงเพื่อทำให้ migration รันซ้ำ

## ตรวจหลังปล่อย

1. Starter เห็นหน้าปลดล็อก Pro และไม่เห็นยอดคลิกส่วนตัวในสตูดิโอ
2. Starter เรียก analytics, CSV และ LINE preview/test โดยตรงไม่ได้; workspace/editor ส่งค่าตัวเลขที่ป้องกันเป็น `null`
3. สมาชิกที่ชำระแล้วและยังไม่หมดสิทธิ์ดูรายงานของตนเองได้ บัญชีหนึ่งดูข้อมูลอีกบัญชีไม่ได้
4. การหมด Pro หยุดการเข้าถึงรายงานและการส่ง LINE แต่ไม่ลบประวัติการเก็บยอด
5. ผู้ใช้ทั่วไปเรียก API หลังบ้านไม่ได้ เจ้าของที่ผูกสิทธิ์แล้วอ่านภาพรวมได้
6. ทดสอบพัก/คืนเฉพาะฮับทดสอบที่ได้รับอนุญาต ตรวจหน้าสาธารณะและประวัติการดำเนินการ อย่าพักฮับจริงของลูกค้าเพื่อทดสอบระบบ

การทดสอบใน `tests/hub-pro-admin.test.mjs` และชุด LINE ใช้ SQLite กับ provider จำลอง ไม่ทำธุรกรรม ไม่ส่งข้อความจริง และไม่เปลี่ยนบัญชีลูกค้าบน production
